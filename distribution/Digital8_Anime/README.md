# Digital8 Anime V4 — PC-8801 / PC-9801 / アニメ塗り

PC-8801 / PC-9801のV4 2色パターン式と、パレットで面を塗り分けるアニメ塗りを一つの画面で使えます。[入力・変換結果のサンプル表](サンプル.md)も参照してください。

## 起動

Python 3.10以降を使用します。実行時の依存関係はPillow・NumPy・Numba・任意のtkinterdnd2です。PSD出力にも追加ライブラリは不要です。

```powershell
python -m pip install -r requirements.txt
python digital8_gui.py
```

`起動_GUI.bat` からも起動できます。起動時は「アニメ塗り標準」・カラーTE・色差128・使用色数24色です。

1. 「選択…」かドラッグ＆ドロップで入力画像を開きます。
2. 「PC-8801標準」「PC-9801標準」「アニメ塗り標準」から選び、パレットや色差を調整します。
3. 「プレビュー更新」で確認し、出力形式と保存先を指定して「変換・保存」を押します。PSDで分け方を選ぶ場合は [レイヤー出力](#png--レイヤーpsd--レイヤーpngのzip) を見てください。

「横幅640pxへ調整」をオンにすると、小さい画像も縦横比を保ったまま横幅640pxに合わせます。オフでは入力画像の寸法で出力します。

「プレビューを自動更新する」は起動時オフです。オンにすると、機種・パレット・数値などの最後の変更から約0.3秒後に計算を始めます。計算中に続けて変更した場合は、終わり次第、最新の設定を反映します。プレビュー窓は一つで、更新時も位置・大きさ・倍率を保ちます。窓を閉じると自動更新をオフにします。

プレビューは100%で始まり、画像1pxを画面1pxとして表示します。倍率は25〜200%、または「画面に収める」へ変更できます。WindowsではTkのウィンドウ作成前に [DPI対応を宣言](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process) して、OSによる画像全体の拡大を防ぎます。

## PNGに設定を保存・復元

GUIの「変換・保存」とCLIのPNG出力には、変換設定を自動で埋め込みます。PNGの `Digital8` というiTXt項目へ、形式の版番号、変換ロジックの版、全変換設定、パレットの実際のRGB、元画像のファイル名とSHA-256、アルファマスクの出力・反転設定をJSONで保存します。絶対パスや元画像の生成プロンプトは保存しません。PNGの画素・透明度は変わりません。

そのPNGをアプリへドラッグ＆ドロップ、または入力画像として開くと、機種・パレット・色差・線の太さ・2倍処理などを復元します。同じフォルダーに元画像があり、ファイルのSHA-256も一致すれば、入力を元画像へ戻します。元画像が見つからない場合は設定だけを復元し、変換済み画像を選択中であることを画面に表示するので、再変換する前に元画像を選んでください。

Customパレットも全機種で保存・復元します。登録済みのパレットが後日変わった場合は、PNGに保存したRGBをCustomとして復元します。設定なしの画像やComfyUI等の別のメタデータは通常の画像として開きます。壊れたDigital8設定は適用せず、画像を開いて状態欄に通知します。

PNGを別のアプリで保存し直すと設定が消える場合があります。元画像自体は埋め込んでいません。旧版で保存したPNGの機種・パレット・数値は読み戻せます。頻出パターン式やグラデーションが指定されていた画像は、V4の2色パターン式と全画面共通の色判定で再変換します。読み込み時に変換ロジックの版の違いを表示します。アルファマスクPNG・PSD・ZIPには今回の設定復元機能を追加していません。

## PC-8801 / PC-9801のパレット編集

パレットを選んで「パレット編集」を押すと、PC-8801は8色、PC-9801は16色のRGBを編集できます。「適用して閉じる」で、その機種の **Custom** に切り替わります。元のプリセットは変更しません。14・15色のPC-9801プリセットは、編集時に末尾の色を複製して16枠にします。色の追加・削除はありません。

各色は `#RRGGBB` または色選択ダイアログで指定し、RGB各成分0〜255をそのまま使います。実機の3bit・4bitの段階への丸めは行いません。JSONの保存・読み込み、変換PNGへの埋め込み・復元に対応します。機種を切り替えても各機種のCustomは起動中保持します。次回起動時はJSONまたは設定入りPNGから読み戻せます。

編集したRGBでタイルの平均色を計算し、主線にはパレット内の最も暗い色を使います。「2倍拡大・1/2縮小」の補間によって、出力には中間色が含まれる場合があります。

CLIでも `--preset pc8801 --palette-file palette.json` または `--preset pc9801 --palette-file palette.json` で指定できます。JSONはアニメ塗りと同じRGB配列形式ですが、PC-8801は8色、PC-9801は16色が必要です。

## PC-8801 / PC-9801の追加タイルと塗り色判定

「V4 2色パターン式（3色追加可）」で、ユーザー提供の追加パターンを使えます。配置は論理ピクセル単位で共通です。PC-8801の縦長ドット表示では各行を2回描画し、PC-9801の正方形ドット表示ではそのまま描画します。

| 設定 | 選択肢 | 初期値 |
| --- | --- | --- |
| 7:1 混色 | 従来4×2／交互4×4（新規） | 従来4×2 |
| 1:1:2 混色 | 使わない／縞4×1／交互4×2／斜め4×4 | 使わない |
| 1:1:1 混色 | 使わない／縞3×1／斜め3×3 | 使わない |

3色の2系列は独立して無効化できます。小さい領域ではタイルの周期が入りきらないため、不要な系列を「使わない」にしてください。3色は選択中の機種パレットから異なる3色を組み合わせ、比率どおりに配置します。基本色そのものを追加する機能ではありません。タイルの位相は画像の左上に固定します。

PC-8801標準とPC-9801標準はV4 2色パターン式です。タイル全体の平均RGBを仮想色として、Photoshop版と同じ全画面共通の色分布・色相判定・平滑化・斑点整理を使います。同じ平均色のレシピは、指定した配置やコントラストの優先度で一つに整理します。「共通色区分数」（2〜64）、「面をまとめる色差」、「周囲をならす半径」、「小さい面の整理」で調整します。通常／2倍処理は元サイズから同じ色基準を作ります。

タイルの指定はPNG設定に保存します。追加前のPNGでは、未保存の項目を従来4×2の7:1・3色なしとして補います。

```powershell
python digital8_converter.py input.png output.png --preset pc9801 --eighth-tone eighth_staggered --three-112 three_112_diagonal --three-111 three_111_stripes
```

## 面の処理と高速化

アニメ塗りとPC-8801／9801で共通の面の検出・小さな斑点の整理はNumbaで実行します。Numbaがない環境では同じ処理のPython実装を使います。

初回は機械語へのコンパイル時間が加わります。コンパイル結果は `__pycache__/` に保存し、次回以降は再利用します。Python・Numbaの更新や処理コードの変更後には再作成される場合があります。GUIの変換は別スレッドで実行し、面の結合処理中はGILを解放します。

`region_kernel.py` に配列だけを扱う面の検出・整理処理を切り出しました。NumbaとPythonの結果が一致することを検証しています。旧方式の色差順の結合処理も比較・回帰確認のために残していますが、現在の塗りでは大きな面の平均色は使いません。

Numba導入時（`d3ef9fc`）に、1520×1280pxの提供サンプル `00505-1900052826.png` で測った値です（Windows、Python 3.11.1、NumPy 2.2.6、Numba 0.68.1）。カラーTE 彩度上げ、24色、色差128、線の太さ0.5、640px調整OFF、色トレスOFFで比較しました。画像・透明度・レイヤー所属・名前は両方式とも完全一致しています。その後に色選びを改良した最新版の変換時間は、下記の `benchmark_regions.py` で再計測できます（PNG保存時間は除外）。

| 処理 | 従来Python | Numba | 全体の速度比 |
| --- | ---: | ---: | ---: |
| 通常 | 18.70秒 | 3.88秒 | 4.82倍 |
| 縦横2倍で変換して縮小 | 79.25秒 | 15.80秒 | 5.02倍 |

コンパイルは別計測で約1.48秒でした。ファイル保存・GUI描画は含みません。単一画像・各1回の測定なので、画像内容・PC・実行時の負荷で変わります。面処理だけの時間は通常16.24→1.39秒、2倍69.50→6.56秒です。局所平均や画像の拡大・縮小などの処理時間は引き続き必要です。

## 2倍拡大・1/2縮小

「2倍拡大・1/2縮小（LANCZOS）」のチェックで切り替えます。初期値はOFFで、3機種に共通です。拡大・縮小とも、Pillowの [LANCZOS補間](https://pillow.readthedocs.io/en/stable/handbook/concepts.html#filters) を使用し、追加のライブラリは不要です。

| 横幅640pxへ調整 | チェックON時の処理順 |
| --- | --- |
| OFF | 入力画像を縦横2倍へ拡大 → 変換処理 → 縦横1/2へ縮小 |
| ON | 横幅640pxへ調整 → 変換処理 → 縦横2倍へ拡大 → 縦横1/2へ縮小 |

最終サイズはOFF時と同じです。640pxがOFFの場合は2倍の画像で線・面・パターンを判定するため、処理画像の画素数が4倍になり、変換時間とメモリが増えます。線幅・仮想ピクセルなどの設定値は2倍画像の処理グリッドで適用されます。640pxがONの場合は通常どおり変換してから拡大・縮小し、仕上がりを少しなめらかにします。

アニメ塗りでは、使用するパレットと全画面の色区分を元サイズの入力から決め、通常／2倍で同じ基準を使います。平滑化は2倍時に2px先の近傍を使い、途中の主線・透明画素・強い色差も確認するため、細い壁を飛び越えません。最初に1px近傍もならして格子の分離を防ぎます。小さい面の整理面積は2倍時に4倍へ換算します。線を太くする処理は換算せず、これまでの挙動を保ちます。補間・主線の検出・境界の違いがあるため、通常／2倍の結果が完全一致するわけではありません。

最終縮小ではRGBの中間色が生まれるので、チェックON時の出力は8色・16色・指定使用色数を超えることがあります。再減色は行いません。透明度も補間し、二値化モードでは最後にしきい値を適用し直します。

プレビュー、PNGとZIP、PSDのタイル模様を保持したレイヤーには同じ仕上げを適用します。レイヤーの所属マップは最近傍で最終サイズへ合わせ、境界の中間色も所属先のレイヤーへ保存するため、タイル模様を保持したレイヤーの再合成は通常の出力画像と一致します。

## カラーTE / カラーCW

ユーザー提供の色票画像から、枠中央の **7×7ピクセルのRGB中央値** を採取したデータベースです。印刷物や実物塗料の測色値ではなく、その画像内の色の近似です。

| パレット | 登録数 | 内容 |
| --- | --- | --- |
| カラーTE | 100 | 東映動画カラーチャート再現画像の99枠＋ユーザー指定の白 `#FFFFFF` |
| カラーCW | 563 | セルワーク画向けチャートの全色票。空欄の背景グレーは除外 |
| カラーTE 彩度上げ | 100 | ユーザーが彩度を調整したTEのデータベース画像から再採色 |
| カラーTE肌+ | 100 | カラーTEの33番を `#FFF4C1`、47番を `#FFE0D3` に変更 |
| カラーTE肌+ 彩度上げ | 100 | カラーTE 彩度上げの同じ2色を、上記と同じ指定RGBに変更 |
| カラーCW 彩度上げ | 563 | ユーザーが彩度を調整したCWのデータベース画像から再採色 |
| Cel120 | 120 | グレー・肌・色相の作業用パレット |
| Custom | 1〜4096 | ユーザーが編集・読み込みした候補色 |

肌+の番号はパレット編集画面の1始まりの番号です。両方の肌+パレットとも33番はRGB `(255,244,193)`、47番は `(255,224,211)` で、指定色への追加の彩度補正は行いません。他の98色はそれぞれの元パレットと同じです。データは `palettes/colour_te_skin_plus.json` と `colour_te_skin_plus_saturated.json` に保存し、変更前のRGBと元データのハッシュも記録しています。

`palettes/colour_te.json` と `palettes/colour_cw.json` に、RGB一覧、各採色点、採色範囲、枠の範囲、元画像のファイル名・サイズ・SHA-256を記録しています。小さい印刷番号の誤読を避けるため、識別子は `TE-R01C01` / `CW-R01C01` のような行・列IDです。**印刷された絵の具の品番を推定したIDではありません。**

「使用色数」で、画像ごとにこの中から使う色数の上限を指定します。初期値24、範囲1〜256、0は全候補色です。面積で重み付けした色の誤差を減らすように候補色を選びます。主線・色トレスも同じ上限に含めます。実際の使用数が上限未満になる場合もあります。

TEの追加の白は通常は白色で出力します。「白(#FFFFFF)を透明にする」を選ぶと、元のアルファを保ちつつ、白に割り当たった部分を透明にできます。CWの色票Wは採取したクリーム寄りのRGBのままで、このチェックの対象ではありません。

「パレット編集」で各色を選び、カラーピッカーか `#RRGGBB` で変更できます。大きいパレットは縦スクロールできます。「適用して閉じる」でCustomへ反映します。その起動中のCustomは機種を切り替えても残ります。再起動後にも使うパレットはJSONへ保存してください。候補色数と、画像ごとの使用色数は別です。

JSONは `{"name":"My palette","colours":[[0,0,0],[255,225,198]]}` の形式です。`colors` キーやRGB配列だけの形式も読み込めます。RGBは0〜255の整数です。

採色を再現する場合は、提供された原寸のチャート画像を指定します。

```powershell
python extract_charts.py TE_chart.png CW_chart.jfif
```

データベースは `palettes/`、採色点を描いた確認画像と位置ID付き色一覧は `preview/charts/` に出力されます。元のチャート画像は同梱していません。

彩度上げ版は `preview/charts/TE_database_彩度上げ.png` / `CW_database_彩度上げ.png` の各枠中央7×7pxから採取し、`palettes/colour_te_saturated.json` / `colour_cw_saturated.json` に別登録しています。元の位置IDと順序は保持しています。こちらで彩度の倍率を推測して作った色ではありません。登録の再現は `python register_saturated_palettes.py` です。元のTE/CWのRGBは変更しません。

## アニメ塗りの仕組みと調整

1. 共通設定で仮想ピクセル、色補正、主線、輪郭抽出、透明度を決めます。
2. 元サイズの補正後RGBから、透明度で重み付けした全画面共通の色分布を作り、使用するパレットを先に選びます。非常に近い候補色は全画面で共通に整理します。
3. 主線を必要な分だけ太くし、上下左右の近い色を周囲数ピクセルから平均化します。主線・完全透明部分・大きな色差は越えません。
4. 局所的にならしたRGBを、全画面共通の色区分から同じルールで塗り分けます。離れた部品でも同じ色区分は同じ塗りになります。タイル・ディザは使いません。
5. 同色の上下左右につながった領域を面として検出し、小さい斑点だけを隣の大きな面へ整理します。主線・透明の壁は越えず、強い色差や反対の色相への塗り替えも保護します。胸の明部と影を一つの大きな平均にするような処理は行いません。
6. 必要なら主線に色トレスを適用します。

| 設定 | 初期値 | 効果 |
| --- | --- | --- |
| 面をまとめる色差 | 128 | 局所平滑化と斑点整理で越えてよいRGB各成分の差。全画面の色分布は値に応じて1〜8RGB刻みで集計し、候補パレット内で各成分が値の1/8以内の近い色を共通化します。0は平滑化・近い候補色の統合を無効にします。 |
| 周囲をならす半径 | 3 | 局所平均の広がりの目安。上下左右の平均化を値の2倍の回数実行。0で無効です。 |
| 小さい面の整理(px) | 12 | この面積未満を近い色の隣の面へまとめる候補にします。0で無効です。 |
| 使用色数 | 24 | 画像全体の使用色数の上限。主線と色トレスも含めます。 |

ユーザーの試用結果に合わせて色差128を標準にしました。細かい影を残したい場合は値を下げます。従来の「近い色をまとめる数」はグローバルな分類数なので、アニメ塗りの色差とは異なる値です。

色選びは、まず色相の適合を優先し、その中で距離を比べます。元の面に色味がある場合（OKLabの `C ≥ 0.02`、`C = √(a²+b²)`）、同じ色相側の色と無彩色を優先し、反対側の有彩色は後回しにします。a/bベクトルの内積が0以上なら同じ側と判定します。白やグレーへの近似も選べるようにすることで、明るい装甲などへ不要な色味を加えないようにします。適合する候補がある限り、明るさや彩度が近くても反対側の有彩色は選びません。候補の優先順が同じ場合の距離は `dL² + 4(da² + db²) + 9dC²` です。

元の面がグレーに近い場合（`C < 0.02`）は、色相が不安定なのでこの制約を使わず、従来の距離で評価します。これにより無彩色に色味を足しすぎない処理を保ちます。以前の「色相反転に有限の罰点を足す」方式では、肌色候補が残っていても薄い青紫が勝つ場合があったため、距離の係数調整から候補の優先順位へ変更しました。

この色相評価は、パレットの使用色の選定、局所色の割り当て、斑点整理の統合可否に使います。色数が少なく同じ色相側の候補が残せないときは無彩色を優先し、候補が反対側の色しかない場合にも処理は続行します。RGBの最大チャンネルを固定するルールや物体認識ではないため、同じ色相側や無彩色への近似は残ります。TE/CWのRGBデータは変更しません。

白い装甲などで同系統の塗りが選ばれやすくなりますが、物体の同一性を認識して色を固定する機能ではありません。影は別の濃い色になり、パレットに近い無彩色がなければ青みのある色などで近似します。候補色や使用色数が極端に少ない場合の色の置き換わりは残ります。

顔・髪・服などの意味を認識して影を描き直す処理ではありません。背景も同じ上限色数の中へ入ります。元画像にある明暗を共通の色区分へ割り当てるため、旧方式より細かい陰影やハイライトが残ることがあります。斑点が気になるときは「小さい面の整理」や「周囲をならす半径」で調整してください。小さい面の整理では近接する元RGBの平均を統合先の選択に使いますが、大きな面の塗り色を決め直すことはありません。

## 線を太くする / 色トレス

88・98・アニメ塗りで共通です。標準プリセットの「輪郭抽出」は3機種とも **1.00** にしました。

- **線を太くする(px)**: 初期値0、範囲0〜16、GUIでは0.25刻みです。0.25/0.50/0.75は、次の1pxの輪郭への濃さを変え、選択済みのパレット色に合わせます。1で上下左右・斜めへ各1論理px、2で各2論理px広げます。小数の見た目がパレットの丸めで同じになる場合もあります。まず0.25〜0.50を試してください。仮想ピクセルや縦長ドット適用後の論理グリッド単位です。アニメ塗りでは透明領域へ線を描き足しません。画素のアルファや使用色数の上限も変えません。
- **色トレス**: 広い暗部を保護し、両側に塗りがある細い主線を対象にします。両側の塗りが同じ距離なら暗い側を優先します。暗さに加えて色相の近さも調べ、適切な濃色がなければ元の線を残します。パレット外に色を作ることはありません。
- **色トレス明度**: 初期値0.55。隣の塗りRGBをこの比率で暗くした色を目標に、利用可能な暗いパレット色を選びます。小さいほど濃い目標です。選択色が少ない場合など、連続的には変化しないことがあります。

幅のある黒ベタを検出して、その縁も保護します。細い主線は上下左右・斜めの反対側にある塗りで確認します。基本幅3論理pxまでを対象に、線を太くした整数部分に合わせて許容幅を増やします。これにより黒い宇宙や星の周囲を、単に「黒と色が隣接している」という理由で染めるのを抑えます。透明の隙間を越えて色は拾いません。目・口などの意味を認識した保護ではありません。

88/98では、タイルの各ドット色ではなく、そのパターン全体の平均色を参照します。8色などで近い色相の濃色がない場合は黒線を維持するため、変化が少ないことがあります。アニメ塗りはトレス用の濃色も考慮したパレット選択を常に行い、トレスのON/OFFで塗り色自体は変えません。

色トレスの考え方: [線画と塗りをなじませる！ 簡単にできる色トレスの方法（いちあっぷ）](https://ichi-up.net/2016/093)

## PNG / レイヤーPSD / レイヤーPNGのZIP

「出力形式」でPNG・PSD・ZIPを選べます。保存先ダイアログから拡張子を指定しても切り替わります。PSDにはタイル模様を保持したレイヤーが必ず入り、PSDを開くとその変換結果が表示されます。

出力形式をPSDにすると、「PSDの追加レイヤー」の2つのチェック欄が使えます。どちらもオフなら、タイル模様を保持したレイヤーを直接保存します。どちらかをオンにすると、これらのレイヤーが「タイル模様を保持」グループに入り、選んだグループが非表示で追加されます。両方をオンにすることもできます。Photoshopで比較するときは、表示したいグループだけ目のアイコンをオンにします。チェック欄はPSD保存時に使い、プレビューには常にタイル模様を保持した画像が表示されます。

- **使用色ごと**にチェックすると、変換結果に現れたRGBごとに分けます。混色タイルの各ドット、色トレス、2倍処理で生まれた中間色もRGBごとにまとまります。
- **塗りごと**にチェックすると、PC-8801／PC-9801で同じ混色タイルを使った範囲を、ドットのRGBを面積比で平均した単色で塗ります。例えば黄色と青の1:1市松は `#808080` です。単色の塗り・主線・透明度を保ちます。アニメ塗りでは塗り色ごとに分け、主線・色トレスは最上段です。

PSDは8-bit RGBで、アルファ付き通常レイヤー・レイヤー名・合成プレビューを保存します。レイヤーは内容のある範囲に切り詰めて位置情報を持ち、RLE圧縮します。1辺30000pxまでです。ZIPはタイル模様を保持し、キャンバスと同じ大きさの透明PNGで各レイヤーを保存します。`manifest.json` に下から上の順序と名前を記録し、`composite.png` も同梱します。

各グループの内側ではレイヤーの可視部分は重なりません。主線が独立しているグループでは、線のレイヤーを非表示にすると線のあった部分が透明になります。

PSDは [Adobe Photoshop File Formats Specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/) に従って出力し、Pillowと、テスト専用に導入したpsd-toolsで読み込みを検証しています。Photoshop 27.11でも、Python版の画面から保存したPC-9801のPSD（256×216px、32レイヤー）を開けることを確認しました。

PSDの互換表示用合成プレビューには半透明ピクセルの白マット処理による8-bitの丸め差が出る場合があり、従来の原寸サンプルではRGB最大1階調でした。

## コマンドライン・比較画像・テスト

```powershell
python digital8_converter.py input.png output.png --preset anime --palette te --anime-max-colours 24
python digital8_converter.py input.png output.psd --preset anime --palette cw_saturated --anime-max-colours 24 --line-growth 0.5 --colour-trace
python digital8_converter.py input.png output.psd --preset pc9801 --psd-layers colour --psd-layers fill
python digital8_converter.py input.png output.zip --preset pc9801 --line-growth 1
python digital8_converter.py input.png output.png --preset anime --white-transparent
python digital8_converter.py input.png output.png --preset anime --smooth-2x --no-resize-640
python digital8_converter.py input.png output.png --preset anime --smooth-2x --resize-640
python make_sample_gallery.py input1.png input2.png --colours 24 --tolerance 48 --line-growth 1
python make_refinement_gallery.py input.png
python -m unittest discover -s . -p 'test_*.py' -v
python benchmark_regions.py output_sample/anime/source/00505-1900052826.png
```

独立したPSD読み込みの検証は、任意で `python -m pip install --target .test-deps psd-tools` を実行すると有効になります。本体の依存には追加しません。

`benchmark_regions.py` は同じ入力・設定で斑点整理のPython実装とNumba実装を比較し、通常／2倍処理の変換時間、斑点整理の時間、画像・透明度・レイヤー所属・名前の完全一致を確認します。画像の読み込みから結果の作成までを測り、ファイル保存時間は含みません。結果は `preview/performance/numba.json` に保存します。コンパイル／キャッシュ読み込み時間は変換と別に記録します。

`make_sample_gallery.py` は原寸でTE・CWを変換し、同じCW塗りに対する黒線／色トレスの比較を作ります。最初の画像はPSDとZIPの見本も保存します。画像・PSD・ZIP・所要時間は `preview/samples/` に出力し、Gitには含めません。時間・メモリはピクセル数と面の数に依存します。大きい画像を試す前に640px版で色や太さを調整することもできます。

`make_refinement_gallery.py` はこのリポジトリのGit履歴を使用する開発用スクリプトです。同じ塗りで旧／新色トレスを3機種で比較し、固定した塗りに対する線の太さの段階比較も `preview/refinements/` に作ります。

README掲載用のサンプルは `generate_readme_samples.py` で作成します。入力PNGの画素・アルファを保ち、カラーTE 彩度上げ、24色、線の太さ0.5、色差128／64、色トレスなしで変換します。最後に先頭画像の色差128・色トレスありを追加します。掲載対象だけを `output_sample/anime/` に保存し、設定・入力と出力のハッシュ・所要時間を `manifest.json` に記録します。

## Photoshop版について

[Photoshop版](../../photoshop/README.md) はUXPパネルとC++フィルタで動きます。Python版もV4のタイルと全画面共通の色判定を使います。Python版からPhotoshopでレイヤーを編集する場合は、レイヤーつきPSDで保存してください。
