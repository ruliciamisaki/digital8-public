# Digital8 Photoshop — UXPパネル 0.3.22 / C++フィルタ 0.2.3

Windows x64のPhotoshop用C++フィルタ `Digital8.8bf` と、操作用のUXPパネルです。変換計算はC++、パネルのUIとPhotoshopの操作はUXP JavaScriptで動作します。実行時にPython、Numba、ローカルサーバー、ネット接続は不要です。

**Photoshop 2026（27.11）でメニュー表示と3機種の通常適用を確認しました。** アニメ塗りでは、スマートフィルタとしての適用、設定を含むPSD保存・再読込、原画を変更した後の自動再計算も検証済みです。実機試験は最大256×256pxの透明・半透明部分を含むテスト画像によるものです。

## ダウンロード

[Digital8 Photoshop 0.3.22 for Windows x64（ZIP）](release/Digital8Photoshop-0.3.22-win64.zip)

ZIPを展開すると、UXPパネル `Digital8Panel-0.3.22.ccx` とC++フィルタ `Digital8.8bf`（0.2.3）が入っています。`release/` には最新版の配布ZIPを1つ置きます。更新時はZIPを差し替え、このリンクを更新します。

## UXPパネルの使い方（推奨）

配布ZIPを展開し、同梱のCCXをダブルクリックしてCreative Cloudからインストールします。インストール後は **プラグイン → Digital8 Native Panel → Digital8** から開きます。パネル読み込みにDeveloper ModeやUXP Developer Toolは不要です。0.3.21以前から更新する場合は、同梱の8bfも差し替えてください。

パレットの名前を押すと候補がパネル内に開きます。候補を選ぶと、パレット名と色見本が切り替わり、次のプレビュー更新や適用に反映されます。

Photoshopを終了し、同梱の `Digital8.8bf` 0.2.3を下記のプラグインフォルダーへ配置してPhotoshopを再起動してください。以前の8bfが配置済みの場合は、同じ場所のファイルを差し替えます。従来のスマートフィルタに保存した設定も読み込めます。

1. RGB 8-bitの画像レイヤーかスマートオブジェクトを1つ選択します。スマートフィルタにしたい場合は先にスマートオブジェクトへ変換します。
2. 既にDigital8がある場合は「既存のDigital8設定を読み込む」で設定とパレットRGBを取り込みます。
3. 機種・パレット・数値を編集します。数値はスライダー、▲▼、直接入力で調整できます。色見本のクリックで色を選び、「RGBを調整」のスライダーやHEX入力で色を変更できます。
4. **「プレビュー更新」でタイル模様を保持した変換結果をメイン画面へ表示**します。「プレビューを自動更新する」がオンのときは、パネルを開いたときや対象・機種・パレット・数値を変えたときにも自動で反映します。連続して設定を変えた場合は最後の操作から約0.3秒後、計算中に変更した場合は処理が終わってから更新します。初期設定はオフで、オン・オフの状態は保存されます。
5. 「適用」で確定し、「取消」で開始前へ戻します。確定は1つの履歴になり、PhotoshopのCtrl+Zで戻せます。

**プレビュー中の数値入力**　手動・自動とも、プレビューの表示中はスライダーや▲▼で数値を調整します。キーボードで数値を直接入力する場合は、「プレビューを自動更新する」がオンならオフにしてから「取消」を押し、数値を入力してください。入力後は「プレビュー更新」で確認できます。

プレビューや適用でエラーが出た場合は、内容をパネル下部に表示します。処理が成功するとエラー表示は消えます。

スマートフィルタの名前をダブルクリックした場合は8bf側の設定画面が開きます。UXPのメイン画面プレビューで再編集する場合は、パネルの「既存のDigital8設定を読み込む」を使用してください。

プレビュー中はPhotoshopをモーダル状態にして入力画像と履歴を保護します。元画像・調整レイヤー・選択範囲などを編集するときは、いったん「適用」か「取消」で終了してください。パネルを閉じた場合も取消を要求します。処理中の中止にはPhotoshop側のEscape／進捗表示も使用できます。

プレビューごとに前回の試し適用を取り消してからC++フィルタを実行します。既存のDigital8スマートフィルタが1つある場合は、そのフィルタの設定を更新します。別のスマートフィルタを追加する処理にはなりません。Digital8が複数ある場合や無効の場合は、対象を整理するよう案内します。既存のスマートフィルタのマスク・描画オプションは維持します。

選択範囲がある通常レイヤーでは、その範囲だけを変換します。スマートフィルタの再編集では、Photoshop側の既存スマートフィルタマスクが使用されます。

### 追加レイヤー出力

画像レイヤーを1つ選択して「適用」を押すと、元レイヤーのすぐ上に `Digital8 — 元レイヤー名` グループを作り、元レイヤーは画素を保ったまま非表示にします。「適用時の追加レイヤー」の2つのチェック欄で、追加するグループを選びます。両方同時に選べます。スマートオブジェクトでは従来どおりスマートフィルターとして適用されます。

グループ内には、チェック欄の状態にかかわらず「タイル模様を保持」が入ります。模様を保ったまま塗りパターンごとに分け、初期状態で表示します。追加グループは非表示から始まります。表示を比べるときは、グループの目のアイコンを切り替えてください。2つのチェック欄は「適用」時の出力にだけ使います。

- **使用色ごと**では、変換結果に現れたパレット色ごとに `#RRGGBB` 名の画像レイヤーを作ります。
- **塗りごと**では、同じ混色タイルを使った範囲をドットのRGBを面積比で平均した単色で塗ります。黄色と青の1:1市松なら `#808080` です。単色や主線の色、半透明は保持します。

選択範囲の外やぼかしのある境界には、Photoshopが合成した画素を使います。有効なピクセルマスクは出力グループに複製します。レイヤースタイルとベクトルマスクは元レイヤー側に保持します。

Photoshopの履歴オプションでレイヤー表示の変更を履歴から除外している場合は、追加レイヤー出力をCtrl+Zで戻したあと、元レイヤーの目のアイコンをオンにしてください。

### UXP版の実機検証（2026-11-11）

Photoshop 27.11、透明・半透明部分を含む256×216px画像で確認しました。

- アニメ塗りのメイン画面プレビュー、設定変更後の再計算、取消後のRGBA完全復元。
- 60×60pxの選択範囲内の変換と、範囲外の全画素維持。取消による完全復元。
- スマートフィルタの確定、1つの履歴への集約、設定スナップショット保存。
- 既存Digital8の再編集、取消時の復元、二重適用が発生しないこと。

UXPパネルの全プリセット、全機種・全設定のUI操作は網羅していません。C++エンジンの3機種比較試験は後述します。新パネルからのPSD再読込後の再編集と、パネルを閉じる操作による取消はまだ個別の実機試験を行っていません。

## C++フィルタ単体のインストールと使い方

1. 上の「ダウンロード」から配布ZIPを取得して展開します。
2. Photoshopを終了し、`Digital8.8bf`を `C:\Program Files\Adobe\Adobe Photoshop 2026\Plug-ins\Digital8Native\` へコピーします。Windowsの管理者権限が必要な場合があります。
3. Photoshopを起動し、**8-bit RGB画像**を開きます。色の比較にはsRGBを使用してください。
4. **フィルター → Digital8 → Digital8 Native…** を選びます。日本語設定画面で機種・パレットなどを選び、「プレビュー更新」で確認して「適用」します。

スマートフィルタを使う場合は、レイヤーをスマートオブジェクトに変換してから適用します。入力画像と設定から毎回再計算する実装で、Action Descriptorへバージョン付きの全設定・パレットRGBを保存します。実機でPSD再読込後もスナップショットが残ることと、スマートオブジェクト内部の画像の明るさを変更して保存すると、フィルタ結果が変わることを確認しました。スマートフィルタをダブルクリックした際の設定画面の再編集と、88/98でのPSD再保存はまだ個別に検証していません。

背景レイヤーや透明度をロックしたレイヤーでは透明度を変更できません。「白を透明」「透明度の二値化」を使う場合は、透明度を編集できる通常RGBレイヤーを使用してください。

## C++フィルタ単体の設定画面

設定画面を暗色に整理し、共通・面の塗り分け・タイル・色補正へ分けました。数値はスライダー・▲▼・直接入力を連動させ、パレットは全色の色見本、選択色のRGBとHEX、色編集を表示します。設定変更時の再計算は行わず、「プレビュー更新」で計算します。

フィルタ単体では設定画面とは別のプレビューウィンドウを使います。メイン画面に反映するプレビューはUXPパネルから使えます。

## 調整レイヤーの色変更を先に反映する

レイヤーの外側に置いた調整レイヤーは、スマートフィルタの後で効きます。元画像と、それにクリッピングした調整レイヤーを両方選び、「スマートオブジェクトに変換」してください。そのスマートオブジェクトにDigital8をスマートフィルタとして適用します。

```
スマートオブジェクト  ← Digital8を適用
  ├ 調整レイヤー（下の元画像へクリッピング）
  └ 元画像
```

色を変更するときはスマートオブジェクトのサムネイルをダブルクリックし、中の調整レイヤーを編集してCtrl+Sで保存します。親文書で「補正済み画像 → Digital8」の順に再計算されます。元画像だけをスマートオブジェクトにして調整レイヤーをその上へ残す配置では、この順序になりません。

## 実装した範囲

- PC-8801 / PC-9801の**2色パターン式＋全画面共通の色判定**、アニメ塗り。
- 現行のプリセットパレット。カラーTE・TE肌+・CW・彩度上げ版・Cel120等を埋め込み。
- 機種別パレットのRGB編集。設定とRGBのスナップショットを保存。
- 仮想ピクセル、縦長ドット、主線しきい値、輪郭抽出、明るさ・彩度・コントラスト・RGB補正。
- 色差、周囲の平滑化、小さい面の整理、使用色数／共通色区分数。
- 市松／縦縞、3:1、7:1、追加の3色タイル。
- 整数・小数の線の太さ、細い主線の色トレス、大きな黒ベタの保護。
- 透明度保持・二値化・白の透明化。入力と出力の画像寸法は同じ。
- 非同期の全画素プレビュー、処理キャンセル。設定取消時は元のフィルタ設定を保持。
- UXPパネルからの自動プレビューと、画像レイヤー適用時の使用色・塗りごとの追加レイヤー出力。
- 32-bit座標、位置のずれた処理領域、パディング付き・負の行ストライド、平面別チャンネル転送。

## 未移植・制限

- **頻出パターン式、従来の色判定、640px調整、2倍処理して縮小、PNG設定の読込**は未実装です。設定画面には表示しません。
- 対象はWindows x64、RGB 8-bit、1回のフィルタ対象が**800万画素以下**。グレー・CMYK・16/32-bitは処理しません。
- RGB数値をsRGBとして扱います。ICCプロファイルの変換は行いません。
- 仮想ピクセル・縦長ドットの補間はネイティブのLANCZOS実装です。Pillowと丸めまで完全に同じではありません。特に半透明画像や小さな画素区分は別途比較が必要です。
- 全画面共通の判定は、Photoshopが渡すフィルタ対象の矩形全体が基準です。選択範囲の有無で結果が変わる場合があります。タイルの原点も対象矩形の左上です。
- PSDに保存する設定の形式は`D8N1`です。未対応形式は既定値へ戻さずエラーにします。今後、アルゴリズム自体を変える場合の旧描画エンジン維持は未実装です。

## 今後の課題

- **カスタムパレットの読み込み・書き出し（保留）**。パネルで現在選んでいるパレットを編集後のRGBごと保存し、読み込んだパレットをカスタムとして使えるようにする。Photoshopでの取り回し、色数の上限、カラーCWなど大きなパレットの扱い、RGBと色順の保持をACOとACTで比較してから、採用する形式を決める。

## ソースからのビルド

リポジトリのルートから、C++開発コンポーネントを入れたVisual StudioとWindows SDKを使って実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File photoshop/build-filter.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File photoshop/build-tests.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File photoshop/build.ps1
python -m unittest discover -s photoshop/validation -p 'test_*.py' -v
python photoshop/validation/compare_renderer.py
powershell -NoProfile -ExecutionPolicy Bypass -File photoshop/package-panel.ps1
```

Photoshopを起動し、本フィルタをインストールした状態なら、次の実機試験も実行できます。公式のCOM/ExtendScript APIを使用し、使い捨ての文書だけに適用します。出力と記録は`build/photoshop-smoke/`です。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File photoshop/validation/run-photoshop-smoke.ps1
```

`build-filter.ps1`は`-SdkRoot`・`-MSBuild`・`-PlatformToolset`を指定できます。ビルド自体にもPythonは不要です。`generate_palettes.py`は開発時に既存パレットのRGBデータから`native/palettes.cpp`を再生成する場合だけ使用します。生成済みC++をリポジトリに含めます。

ソースからビルドする場合は、[Adobe Photoshop C++ SDK](https://github.com/AdobeDocs/photoshop-cpp-sdk) を別途用意し、`-SdkRoot` で指定します。SDKと `build/` の開発用生成物はGit追跡対象外です。`release/` に置く配布ZIPからインストールでき、SDKソースの同梱はありません。SDKヘッダー由来の文字コード警告C4828は残っています。

Windows用のインストール先は[Adobe公式のプラグインフォルダー案内](https://helpx.adobe.com/photoshop/desktop/troubleshoot/tool-feature-issues/photoshop-plug-in-folder-locations.html)を参照しています。

## UXPパネルの開発と検証

`uxp/native-data.json`はC++から書き出した設定レイアウト、既定値、パレットRGBです。新しい設定やパレットを追加した際は、ビルドした開発用CLIで更新します。PythonやNodeはパネル実行時に不要です。

```powershell
photoshop/build/validation/native_cli.exe --export-panel photoshop/uxp/native-data.json
node --test photoshop/validation/uxp.test.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File photoshop/package-panel.ps1
```

Nodeテストではパレット選択時の色見本と設定の更新、設定のC++往復、更新・取消・確定・失敗・Escape、既存フィルタの更新指定と対象確認を検証します。`package-panel.ps1 -Validation`は自動実機試験用のCCXを別に生成します。これは読み込み時に使い捨て画像で試験を実行する開発専用パッケージです。通常のCCXには試験スクリプトと画像を含めません。実機記録は `build/uxp-host-test.json`、パネル操作とCtrl+Zの画素比較は `build/uxp-ui-test.json` に保存しています。

パネルはAdobeの[executeAsModalと履歴の中断・復帰](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/executeasmodal)、[redrawDocument](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/media/photoshopcore)を使用します。CCXはAdobeの[UPIA](https://developer.adobe.com/uxp/guides/how-to/distribution/install/)からこの環境へ導入して検証しました。
